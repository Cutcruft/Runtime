# Демо-плагин (эталон)

Демо-плагины показывают, как писать плагины против `io.runtime:runtime-sdk`, и являются эталоном использования API. Два плагина:

| Плагин | Каталог исходников | Id | Что демонстрирует |
|---|---|---|---|
| `demo` | `demo-plugin/` | `demo` | Две сущности со связью через `ObjectRef`, команды на все операции `ObjectList`, атомарные серии под `withProjectLock`, `references`, UI на каждый экран |
| `demo-storage` | `demo-storage-plugin/` | `demo-storage` | **Зависимость плагинов** (`dependencies` в `config.yaml`), работа с чужими сущностями по строковому `EntityType` без общих классов, экспорт через Jackson |

## 1. Структура `demo-plugin`

```
demo-plugin/
├── pom.xml                          # finalName = demo → target/demo.jar
├── config.yaml
└── src/main/kotlin/com/example/demo/
    ├── DemoPlugin.kt                # Plugin + UIDefinition + регистрация всего
    ├── Board.kt                     # модель доски
    ├── Task.kt                      # модель задачи (ссылка на доску через ObjectRef)
    ├── BoardDefinition.kt           # EntityDefinition для demo.board
    ├── TaskDefinition.kt            # EntityDefinition для demo.task
    ├── DemoIds.kt                   # константы типов и парсинг id
    ├── BoardCommands.kt             # demo.createboard / listboards / deleteboard
    └── TaskCommands.kt              # demo.create / list / complete / delete / stats
```

`config.yaml`:

```yaml
id: demo
version: 1.0.0
apiVersion: 1
main: com.example.demo.DemoPlugin
```

## 2. Модели и связь через `ObjectRef`

Ядро не знает связей между сущностями. Связь описывается моделью плагина — полем с `ObjectRef`:

```kotlin
data class Board(
    val name: String,
    val description: String = ""
)

data class Task(
    val title: String,
    val status: String,
    val board: ObjectRef? = null      // ссылка на demo.board
)
```

`ObjectRef` содержит `entityType` + `objectId` и сериализуется ядром (Jackson) как обычное поле. Доска создаётся через `ObjectList.create` (генерирует UUID), задача получает ссылку на неё.

Определения сущностей:

```kotlin
object BoardDefinition : EntityDefinition {
    override val type: EntityType = EntityType("demo.board")
    override val modelClass: Class<*> = Board::class.java   // используется при save/load
}
```

## 3. Команды

| Id | Параметры | ObjectList-операции | Назначение |
|---|---|---|---|
| `demo.createboard` | `name`, `description?` | `create` | Создать доску |
| `demo.listboards` | — | `values` | Список досок |
| `demo.deleteboard` | `id` | `get` + `delete` + `list` | Каскадное удаление доски и её задач |
| `demo.create` | `title`, `boardId?` | `create` (+ `getObject` для проверки доски) | Создать задачу |
| `demo.list` | `boardId?` | `values` (фильтр) | Список задач |
| `demo.complete` | `id` | `get` + `update` | Пометить задачу `done` |
| `demo.delete` | `id` | `delete` | Удалить задачу |
| `demo.stats` | — | `values` | Статистика: total/open/done |

Имя команды — короткое (`[a-z][a-z0-9]*`), полный id: `<pluginId>.<name>`.

### 3.1 Атомарная серия: `withProjectLock`

Создание задачи проверяет существование доски и создаёт объект как одну атомарную операцию:

```kotlin
class CreateTaskCommand : Command("create", "Create a task") {
    override suspend fun execute(context: CommandContext, params: Any?): CommandResult {
        val p = params as? Map<*, *> ?: return CommandResult.error("Missing parameters")
        val title = p["title"] as? String ?: return CommandResult.error("Missing title")
        return context.withProjectLock {
            val boardRef = when (val boardIdStr = p["boardId"] as? String) {
                null -> null
                else -> {
                    val boardId = runCatching { ObjectId(java.util.UUID.fromString(boardIdStr)) }.getOrNull()
                        ?: return@withProjectLock CommandResult.error("Invalid boardId: $boardIdStr")
                    val board = context.getObject<Board>(BOARD_TYPE, boardId)
                        ?: return@withProjectLock CommandResult.error("Board not found")
                    ObjectRef(BOARD_TYPE, boardId)
                }
            }
            val task = Task(title = title, status = "open", board = boardRef)
            val ref = context.objectList<Task>(TASK_TYPE).create(task)
            CommandResult.success(value = task, references = listOfNotNull(ref, boardRef))
        }
    }
}
```

`references` перечисляет все затронутые объекты — это основа аудита и replay. Каскадное удаление возвращает `references` доски **и** удалённых задач:

```kotlin
class DeleteBoardCommand : Command("deleteboard", "Delete a board and its tasks") {
    override suspend fun execute(context: CommandContext, params: Any?): CommandResult {
        val p = params as? Map<*, *> ?: return CommandResult.error("Missing parameters")
        val id = parseId(p) ?: return CommandResult.error("Missing or invalid id")
        return context.withProjectLock {
            val boardList = context.objectList<Board>(BOARD_TYPE)
            val taskList = context.objectList<Task>(TASK_TYPE)
            val board = boardList.get(id) ?: return@withProjectLock CommandResult.error("Board not found")

            val affected = mutableListOf<ObjectRef>(ObjectRef(BOARD_TYPE, id))
            var deletedTasks = 0
            taskList.list().forEach { ref ->
                val task = taskList.get(ref.objectId) ?: return@forEach
                if (isTaskOfBoard(task, id)) {
                    taskList.delete(ref.objectId)
                    affected += ref
                    deletedTasks++
                }
            }
            boardList.delete(id)

            CommandResult.success(
                value = mapOf("deleted" to id.value.toString(), "deletedTasks" to deletedTasks),
                references = affected
            )
        }
    }
}
```

### 3.2 UI

UI декларативен и описывается `UIDefinition` (компонент `UiComponent`):

```kotlin
context.registerUi(UiComponent("Page", mapOf("id" to "tasks", "title" to "Tasks")))
context.registerUi(UiComponent("Navigation", mapOf("id" to "nav-tasks", "label" to "Tasks", "pageId" to "tasks")))
context.registerUi(UiComponent("Table", mapOf("pageId" to "tasks", "entityType" to "demo.task")))
context.registerUi(UiComponent("Button", mapOf("label" to "New Task", "command" to "demo.create")))
```

Ядро собирает из `Page`/`Navigation`/`Table`/`Button` конфигурацию и отдаёт её во `GET /config`; фронтенд строит интерфейс без знания плагинов.

## 4. Зависимость плагинов: `demo-storage`

`demo-storage` не определяет сущностей — он работает с данными `demo` (доски и задачи) и объявляет зависимость в `config.yaml`:

```yaml
id: demo-storage
version: 1.0.0
apiVersion: 1
main: com.example.demo.storage.StoragePlugin
dependencies:
  - plugin: demo
    version: "1.x"
```

Ядро сортирует плагины топологически (`DependencyResolver`): `demo` загружается до `demo-storage`, циклы обнаруживаются и блокируют запуск.

### 4.1 Работа с чужими сущностями без общих классов

Каждый плагин получает собственный `PluginClassLoader` (parent-first, родитель — ядро). **Модельные классы плагинов между собой не разделяются**: `demo-storage` не может импортировать `Task` из `demo`. Кросс-плагинный доступ работает через:

- строковый `EntityType` (`"demo.task"`, `"demo.board"`);
- `context.objectList<Any>(type)` — без типизации (значения остаются экземплярами моделей `demo`, но плагину не нужен их тип);
- Jackson для сериализации значений (класс берётся из рантайм-типа, не из кода плагина).

```kotlin
class ExportCommand : Command("export", "Export demo data as JSON") {
    override suspend fun execute(context: CommandContext, params: Any?): CommandResult {
        val boards = context.objectList<Any>(BOARD_TYPE).values()
        val tasks = context.objectList<Any>(TASK_TYPE).values()
        val json = DemoJsonMapper.mapper.writeValueAsString(mapOf("boards" to boards, "tasks" to tasks))
        return CommandResult.success(value = json)
    }
}

class CountsCommand : Command("counts", "Count objects per entity type") {
    override suspend fun execute(context: CommandContext, params: Any?): CommandResult {
        val boards = context.objectList<Any>(BOARD_TYPE).size()
        val tasks = context.objectList<Any>(TASK_TYPE).size()
        return CommandResult.success(value = mapOf("boards" to boards, "tasks" to tasks))
    }
}
```

Jackson объявлен в pom плагина со scope `provided` — он уже есть в classpath ядра, поэтому в JAR плагина не попадает:

```xml
<dependency>
    <groupId>com.fasterxml.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>2.17.2</version>
    <scope>provided</scope>
</dependency>
```

## 5. Сборка и запуск

```bash
make plugin    # SDK + оба плагина → plugins/demo/ и plugins/demo-storage/
make dev       # запуск Runtime (конфигурация читается из config/application.yaml)
```

Директории плагинов подхватываются discovery: каждая поддиректория `plugins/` с `config.yaml` и JAR становится плагином.

Проверка `GET /config`: в `commands` видны и `demo.*`, и `demo-storage.*`; в `entities` — `demo.board`, `demo.task`.

## 6. Пример WS-сессии

```
> {type: command.execute, payload: {commandId: project.create, params: {}}}
< {status: SUCCESS, value: {projectId: "..."}}

> {type: command.execute, payload: {commandId: demo.createboard, params: {name: "Backlog"}}}
< {status: SUCCESS, value: {name: "Backlog", description: ""},
   references: [{entityType: demo.board, objectId: ...}]}

> {type: command.execute, payload: {commandId: demo.create, params: {title: "T1", boardId: <boardId>}}}
< {status: SUCCESS, value: {title: "T1", status: "open", board: {entityType: "demo.board", objectId: ...}},
   references: [{entityType: demo.task, objectId: ...}, {entityType: demo.board, objectId: ...}]}

> {type: command.execute, payload: {commandId: demo-storage.counts}}
< {status: SUCCESS, value: {boards: 1, tasks: 1}}

> {type: command.execute, payload: {commandId: demo.deleteboard, params: {id: <boardId>}}}
< {status: SUCCESS, value: {deleted: <boardId>, deletedTasks: 1}}

> {type: command.execute, payload: {commandId: project.save}}
< {status: SUCCESS, value: {projectId: ..., data: "{\"objects\":{\"demo.board\":[...],\"demo.task\":[...]}}"}}
```

Параметры всегда передаются в `payload.params`; `projectId` для `project.create`/`project.open` — тоже там. Результат `command.result` содержит `value` как типизированный JSON и `references` затронутых объектов. Перепривязка сессии на другой проект возможна в любой момент через `project.create`/`project.open`.
